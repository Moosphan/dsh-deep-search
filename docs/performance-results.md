# 性能优化结果（1.4.0）

## 基准方法

使用可重复的合成语料，避免依赖真实会话内容：

- 61 个会话：1 个 200,000 事件的超大会话，60 个 150 事件的近期会话。
- 大会话故意排在列表第一位，模拟最坏的冷启动顺序。
- 查询 `needle`，统计首屏返回、建索引完成时间。
- 解析基准：60,000 个事件的单会话；增量场景追加 2 个事件。
- 环境：Apple Silicon / Node.js 24；暖缓存数据取 3 次运行中位数。

## 优化前 vs 优化后

| --- | --- | --- | --- |
| 单会话全量解析（60k 事件） | 约 158 ms | 约 68 ms（无点路径预过滤） | **约 57% 降低** |
| 增量追加 2 事件（60k 会话） | 约 158 ms | 约 13 ms | **约 92% 降低** |
| 增量缓存写入（60k 文档） | 58.2 ms / 8.1 MB | 0.4 ms / 313 B（delta） | **约 99% 降低** |

## 本版实际改动

1. **live 会话增量解析**：缓存 `lastSeq`、turn/step 与 toolNames；只解析序号大于游标的新事件。遇到序号回退自动全量重建。
2. **冷启动 recent-first**：按 `updatedAt` 排序，先索引最近会话；首屏在 55 ms 返回 20 组近期结果，不再被超大会话堵住。
3. **异步缓存压缩**：gzip 压缩移出同步路径；缓存解压保留同步快路径。
4. **delta 分块缓存**：live 会话只写新增文档块，基准缓存不重写；8 个 delta 后自动合并。
5. **流式结果缓存**：相同查询/筛选在 15s 内直接回放，避免重复全量扫描。
6. **长列表渲染**：分组启用 `content-visibility`，减少视口外 DOM 绘制。
7. **路径无点预过滤**：不含 `.` 的文本不进入路径正则，降低大会话解析 CPU。
8. **回归测试**：增量解析与 delta 缓存一致性测试，当前 19 项全部通过。

## 实验未采用

- **Worker 线程解析 + 并行建库**：合成基准冷建 831 ms → 2,171 ms，首屏 49 ms → 62 ms；structured clone 与 worker 启动成本大于收益，已回退。真实冷建仍约 130 s，后续应做按需索引/倒排索引，而不是直接搬 parse 到 worker。

## 尚未完成

- 按需索引：尚未实现；首次全量读取仍会读所有会话。
- 关键词倒排索引：查询仍是全量线性扫描，32 ms 在当前语料可接受，百万段后需要。
- 结果列表：已加 `content-visibility` 的轻量优化，完整 windowing 仍未做。

## 结论

本版主要解决的是**冷启动首屏**和**live 会话重复解析**，不是查询吞吐。真实生产环境的暖缓存首屏约 641–699 ms（含缓存加载与 facets），查询本身约 27–36 ms，重复流式查询约 2 ms。增量解析会在后续 live 刷新中持续生效。

真实冷建（71 会话、153 MB 文本）此前约 130 s，本轮未重测；首次全量读取仍是主要成本，Worker 化是下一步。
